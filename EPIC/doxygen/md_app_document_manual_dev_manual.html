Clog

各 project ごとに Logger.hpp を logic/へ配置する。ここでマクロ API の生成と設定を行う。 CLog::LogDirector& get_logger()で表示する最低の loglvl と出力の設定(復数可)が可能 現状自由度が高すぎるので変更予定

詳細はこちら:s

マクロ API:

logging

マクロ log lvl
LOGD debug
LOGI info
LOGW warning
LOGE error

LOG_(const char* format, ...) マクロ内で cTag のコンパイル時検証と cformat を行ったあと出力関数に渡している logging は printf のように c 言語 format が可能。

STREAM

  • STREAM_SETUP(int count) 起動時のはじめにこれを呼び出し使用チャンネル数を渡すこと。 これは config.h の C 言語 enum LogChannel の CH_COUNT を渡すことで行う。 この時に split screen の format がされるため再接続のたびに break signal を送るなどし再起動が必要
  • STREAM(CH_index,const char* format, ...) config.h の LogChannel を渡すため index ベースの指定方法にしてある こちらも c 言語の format が可能

CanSystem

構造

CanInterfaces.hppでの FDCAN IFdcanMgr と CAN ICanMgrはどちらもICanControllerを継承した interface である。 ここに使用時の profile インスタンスに含まれるすべての関数のプロトタイプがある

その後abstract/にて実装が
impl/には profile が書かれる.ここでは can の割り込み設定と TxHeader また sFilterConfig の設定が config 行われる
abstract->実装、impl->profile など命名変更予定 基本の profile は can/fdcan のものまた can 互換 fdcan がそれぞれ全 id パスで設定されている カスタムの設定を行う場合は新しい profile を書くか profile の一つを生成して config を取得、編集して適用しなおす。取得と適用の関数がある

使用

使用時は profile に対応した can hanler stract を渡してインスタンスを生成する ライブラリ内でこのインスタンスは ICanController& can/can Mgr& のどちらかで受け取れる 基本的にICanController で受け取ることで can/fdcan に関わらずに動くライブラリになる ただし各 mgr 特有のものは使用不可になる

インスタンス生成と profile 設定:

{c++}
- FdCanCompatImpl(FDCAN_HandleTypeDef &hfdcan, uint32_t stdid = 0)
stdidは削除予定
- bool initCan(const char *_name, int _stream_pos, bool _restart_on_error = false, bool _show_config = false)

他の関数も含め使用方法は doxygen コメントを確認すること(まだしっかり書いていない)

STREAM

注意点

  • 接続するたびに再起動すること。 起動時にしか STREAM の console format ASCII が送信されないため
  • 割り込み中に printf は使用しない CAN の送受信の妨げになったり、console format が崩れてしまうためだ 現状 LOGE と LOGW しか割り込み内で使われないが、これは電流制限なども含まれるためもし修正する気がなければNO_LOGを define して STREAM のみにすること
  • F0 では Cansystem と Clog 等を使わない 32kb の FLASH RAM しか無いためである。かわりに lite module にあるものを使う。(can interface を継承したものにする予定) また lite を使っていても色々付け足すと 32kb ギリギリになることがあり意味がわからないエラー(HardFault による強制停止)が発生するため std でなく etl を使う
