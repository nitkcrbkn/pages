CanSystem

CanSystem は、STM32 の CAN / FDCAN HALペリフェラルを抽象化するヘッダオンリーのハードウェア抽象化レイヤーです。 CAN/FDCAN の差異と HAL の煩雑な初期化・割り込み・送受信を ICanController という共通インターフェースで定義しています　

設計思想と概念

STM32 の CAN と FDCAN は、HAL 型 (CAN_HandleTypeDef / FDCAN_HandleTypeDef)、フィルタ設定、送信ヘッダ、割り込み登録の作法がすべて異なります。アプリケーションがこれらに直接依存すると広範な書き換えやが必要になります。CanSystem はHAL ハンドルを受け取りこの差異を吸収し、送受信・初期化・コールバック登録を提供します すべてのプロファイルは抽象基底 ICanController を実装します。アプリケーションはこの型のみに依存することで実装が何であるかを知りません。 細かいAPIはICanManager、IFdCanManager を通じてアクセスします。

使い方

initCan() で初期化 → register_cb() でコールバック登録 → send() で送信、が基本の流れ 詳細はexamples/canを参照してください。

FDCANは内部で自動でHALに対して自分自身を割り込み関数として登録するためconfig.hで書く必要は無いです。
対してCANではこれが行われないためスケッチのconfig.hで

void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan) {
can.onMsgReceived(hcan);
}

を書く必要があります。

stream_pos は Clog の STREAM 行スロットの開始位置です。CanSystem は状態表示にこれを起点に複数スロットを使います。
FDCANは3行stream_pos: クイック統計 / stream_pos+1: TxRx 統計 / stream_pos+2: 設定。コンストラクタで設定表示を指定できます。

利用者は register_cb() で std::function<void(const CANMessage&)> を任意個登録できます。全てのフレームがそれぞれのcbに渡されるためcb上部でcan IDでフィルターします。

エラー検出・自動復旧

check_is_error() でバスエラー状態を確認できます。自動復旧（Bus-Off等からの再起動）は new_state_print()（状態表示用、統計出力のみを行う）からは呼ばれないため、復旧させたい場合はmain loop等から restart_handler() を明示的に周期呼び出ししてください。restart_handler() は内部で RETRY_AFTER 間隔を空けてから check_is_error() を確認し、エラーなら restart()（FDCANは失敗時さらに force_restart()）を実行します。

NO_CAN_TRACKER を定義すると、CanManager（Classic CAN）は CanErrorTracker（ID統計・文字列整形込みの重いトラッカー）を使わず、HALレジスタ（ESR）を直接読む軽量な check_is_error() に切り替わります（Flash/RAM制約の厳しいターゲット向け）。NO_CAN_TRACKER 時は new_state_print()（統計表示）自体が存在しなくなりますが、check_is_error()/restart_handler() は引き続き使えます。**NO_CAN_TRACKER は FDCAN（FdCanManager）と併用できません**（USE_FDCAN と同時定義するとコンパイルエラーになります）。

詳細設計

レイヤー構造と責務

CanSystem は 3 系統のディレクトリで構成されます。

  • core/ : 抽象インターフェースと実装基底。CAN/FDCAN 共通の送受信・割り込み・コールバック配信ロジックの中核
  • profile/ : 具象クラス群。core の実装基底を継承し、フィルタと送信ヘッダを具体的に設定 (setConfig / setInterrupt) する
  • support/ : 状態監視。エラーカウンタ・バス状態・ID 統計を収集し、fdcan/canで統一してClog STREAM 向けの表示文字列を生成する

アーキテクチャ

CanSystem 内部のレイヤーとスタックにおける位置づけ:

レイヤー 本モジュールでの実体 責務
Profile FdCanCompatExtProfile 等 フィルタ・Tx ヘッダの具体設定、割り込み有効化
Manager FdCanManager / CanManager 送受信・コールバック配信・再起動・エラー追跡の中核
Interface ICanController / I*Manager 上位への共通 API
HAL STM32 HAL (HAL_FDCAN_* / HAL_CAN_*) ペリフェラルレジスタ操作

受信フロー

  1. CAN ペリフェラルが RxFIFO に格納 → 受信割り込み発生
  2. HAL の登録された静的関数 onMsgReceived() が呼び出される。(fdcanは間にもう一つある)
  3. CANMessage(Identifier, RxData, DataLength) を生成しinvoke_cbs()が実行される

テスト (MockCanProfile)

MockCanProfile は ICanController を実装したモックで、ホスト上の単体テストやcanを使用しないで実機動作をさせるときに使います。initCan / setConfig / setInterrupt は何もせず、send() は送信履歴に積むだけです。ループバックを有効にすると、send() したメッセージが即座に自身の受信コールバックに配信されます。
