Writerが満たすべきインターフェース(コンセプト)

ビットストリームを実際にLEDへ送出する。HAL依存の実装は <platform/led_driver.h> にある。

struct XxxWriter {
bool write(const uint8_t* data, size_t len);
bool busy() const;
};
覚え書き
write()は非同期(DMA)でも同期(ブロッキング)でもよい。 非同期の場合、送出完了までdataは書き換えないこと。

NeoPixel系デバイスの共通基底クラス

ピクセルバッファの保持・色の書き込み・送出を担当する。 CRTP(Curiously Recurring Template Pattern)により、派生クラスの map_index() を仮想関数なしで呼び出す。

派生クラスは以下を提供すること:

  • static constexpr size_t map_index(size_t logical) 論理インデックスを物理(信号線上の並び順)インデックスへ写像する
テンプレート引数
Derived派生クラス自身(CRTP)
Writerビットストリーム送出クラス
PIXEL_COUNTLED数
ORDERチップのch送出順
Codecバイト列のエンコード方式
覚え書き
本クラスはvirtual関数もvirtualデストラクタも持たない。 基底クラスのポインタ経由でdeleteしないこと(そもそも動的確保しない)。
バッファに入るのは画素データだけで、フレーム区切りのリセット期間は 含めていない(show()が時間で担保する)。詳細はshow()を参照。
描画バッファと送出バッファは同一で、DMA送出はこのバッファを直接読む。 そのため送出中(busy()がtrue)の描画APIは何も書き込まずfalseを返す。 DMAが読んでいる途中のバッファを書き換えると、混在したフレームが LEDへ送られてしまうため。描画が落ちては困る場合はbusy()を見て 送出完了を待つか、show()の直後に描き始めること。

バッファをLEDへ送出する

戻り値
以下のいずれかでfalse
  • 前回の送出が未完了 (busy)
  • 前回の送出から MIN_SHOW_INTERVAL_MS 経っていない
  • Writerが送出開始に失敗した

NeoPixelは「一定時間Lowが続く」ことをフレームの区切りとして扱う。 この待ち時間はバッファに0を詰めても実現できるが、それは常時RAMを 占有するので、ここでは時間で判定している。 最後に送出するbitのシンボルは必ず0で終わる(0b100 / 0b110)ため、 送出後のMOSIはLowに留まる。あとは次のshow()を遅らせればよい。

1フレームの送出にかかる時間 [ms] (切り上げ)

IDEAL_HZではなくCodecが許容する最低クロックで見積もる。 実際のビットレートはcheck_config()が [MIN_HZ, MAX_HZ] に収まることしか 保証しないため、理想値で計算するとMIN_HZ寄りに設定されたときに 実送信時間がこの値を超え、末尾のラッチ時間を確保できなくなる。
